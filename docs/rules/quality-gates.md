# 规则：质量闸门

> 本文件定义不可违背的代码与文档质量闸门规则。
> 具体工具可将本文件内容映射为各自的红线规则格式。

## 代码质量

1. **测试通过**：推荐 TDD（红灯 → 绿灯 → 提交）。验证非协商——必须有测试 / 构建 / 运行证据，跑通不算完。
2. **无占位符**：代码中无 TBD / TODO / 待定 / 适当处理 等模糊词。
3. **DRY / YAGNI**：不重复、不预建未用能力（DAMP > DRY，意图清晰的重复优于强行抽抽象）。
4. **密钥安全**：密钥 / `.env` 不入 git、不打印日志。
5. **提交规范**：Conventional Commits（`type(scope): description`），`type ∈ feat / fix / docs / spec / refactor / chore`。
6. **Lint 通过**：项目配置的 linter / formatter 无新增违规。
7. **类型检查通过**（如项目启用）：type checker 无新增错误。

## 量化阈值（稳定性五板斧 + 硬门槛）

> 来源：金线"稳定性五板斧" + 业界量化共识（如 agent-skills）。让质量从"定性感受"变"可机器审查"。

1. **可读性（意图优先）**：命名 / 结构让人一眼懂"要做什么"；不靠注释补意图，靠代码本身体现。
2. **变更粒度门禁**：单次 PR / 提交改动尽量 ≤ ~100 行；过大拆分，便于审查与回滚。
3. **复杂度上限**：单个函数 / 模块控制在合理规模（经验阈值 ≤ ~500 行，超则拆）。Rule of 500。
4. **错误处理**：不吞异常，Fail Fast；错误有清晰传播路径与必要的日志。
5. **可测试性**：依赖外部（DB/网络/时钟/随机）通过 DI 注入；核心逻辑为可独立测试的纯函数。
6. **测试比例（测试金字塔）**：单测 ~80% / 集成 ~15% / E2E ~5%，优先单测覆盖核心逻辑。

## 安全基线（OWASP 视角）

1. **输入验证**：所有外部输入在边界处校验（类型 / 范围 / 长度），不信任调用方。
2. **三层边界**：外部输入 → 业务处理 → 外部输出，层间不泄漏内部细节；敏感数据不越界。
3. **注入防护**：SQL / 命令 / 模板等使用参数化 / 转义，杜绝拼接。
4. **密钥与凭证**：不入 git、不打印日志、不写死在前端；用环境变量 / 密钥管理。
5. **最小权限**：默认最小权限，不滥用全局 / 管理员能力。

## 反理性化表（闸门防绕过）

> 当有人/AI 想跳过上面的闸门时，用此表驳回。来源：业界 skill 的"借口 vs 反驳"机制。

| 借口（Excuse） | 反驳（Rebuttal） |
|---|---|
| "后补测试" | 拒。先测后优；没测试=没验证，违反金线"可验证"。 |
| "这改动太小不用审" | 小改动也能埋雷；走最小 diff 审查即可，不是免审。 |
| "先跑通再说" | "跑通"≠"对了"；必须按金线三问给证据。 |
| "抽出来太麻烦，先复制" | DRY 长期债；但 DAMP 优先——重复清晰胜强行抽象。 |
| "异常先吞了不影响主流程" | 埋雷。Fail Fast，至少记录，让问题可见。 |
| "这逻辑以后可能复用，先建好" | YAGNI。没明确需求不预建。 |

## 文档质量

1. **改代码 → 同 diff 补 docstring**（如项目采用 docstring → reference 机制）。
2. **引入外部依赖 / 接口对接** → 必须建 `docs/integration/` 契约文档。
3. **推翻旧架构决策** → 新增 ADR 标记旧 ADR `Superseded`（旧正文不改）。
4. **行为变更的功能** → 对应 how-to / tutorial 机会式更新。
5. **`docs/README.md` 索引已同步**（增删文档即更新）。

## Verdict 双检

实现完成后，verdict 阶段做两检：
- **阶段一**：规格符合性（proposal 目标是否全部达成）
- **阶段二**：代码质量 + 文档同步
